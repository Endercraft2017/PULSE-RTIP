================================================================================
PULSE-RTIP — SETUP AND RUN INSTRUCTIONS
================================================================================

This file explains how to get the project running on your own machine, for
local development and testing. For what the project is and how it's put
together, see README.md.

--------------------------------------------------------------------------------
1. PREREQUISITES
--------------------------------------------------------------------------------

- Node.js 18 or newer, with npm (comes bundled with Node.js)
- To also build/test the Android app: a JDK (installing Android Studio
  includes one) and the Android SDK (also installed by Android Studio),
  plus an emulator or a physical device with USB debugging enabled

Nothing else is required to run the backend — the default mode uses a local
SQLite database file, so there's no separate database server to install.

start.bat and install-on-phone.bat both check for these on their own before
doing anything else. If something's missing, each one asks:

  Install <thing> automatically now (via winget)? [Y,N]

Answer Y and it installs it there and then (using Windows' built-in
package manager, winget) and carries on. Answer N and it instead offers
to just open the right download page so you can install it yourself.
Either way, nothing gets installed without you being asked first.

If the install itself fails (no internet, a UAC prompt got dismissed,
etc.), it tells you winget's error code, offers to try once more, and
if that fails too, falls back to the download-page offer instead of
just giving up silently.

The one exception is the Android SDK itself: if that's missing, the
script can install Android Studio for you, but finishing the SDK setup
needs Android Studio's own first-run wizard (choosing components,
accepting licenses) — that part has to be done by hand, once, after the
install finishes.

--------------------------------------------------------------------------------
2. RUNNING THE SERVER (WEB + API)
--------------------------------------------------------------------------------

Easiest way:

  Double-click start.bat in the project root.

That script will, in order:
  1. Copy src/backend/.env.example to src/backend/.env if you don't already
     have one (default: offline/SQLite mode, port 3000).
  2. Run "npm install" in src/backend if dependencies aren't installed yet.
  3. Print the addresses the server is reachable at:
       - http://localhost:3000            (this machine only)
       - http://<your LAN IP>:3000        (other devices on the same WiFi)
  4. Start the server in its own window and open the site in your browser.

Manual equivalent, if you'd rather run it yourself:

  cd src/backend
  copy .env.example .env      (first time only)
  npm install                 (first time only)
  npm start

The server hosts both the API (http://localhost:3000/api) and the web
frontend (http://localhost:3000) from the same process.

--------------------------------------------------------------------------------
4. BUILDING AND INSTALLING THE ANDROID APP
--------------------------------------------------------------------------------

  Double-click install-on-phone.bat

That script will:
  1. Sync the frontend + native plugins into the android/ project
     (npx cap sync android)
  2. Build a debug APK with Gradle
  3. Look for a phone connected via USB with debugging enabled, and install
     the APK automatically
  4. If no phone is found, it tells you where the built APK is
     (android/app/build/outputs/apk/debug/app-debug.apk) so you can copy it
     over and install it manually

If Gradle throws "Could not read workspace metadata" or similar cache
errors, run repair-gradle.bat once, then try building again.

--------------------------------------------------------------------------------
5. POINTING THE APP AT A LOCALLY-HOSTED SERVER
--------------------------------------------------------------------------------

The installed app normally expects a fixed hosted server address. If you're
testing against a server you're running locally instead (via start.bat on
your own machine), that address will be different every time you're on a
different WiFi network.

To handle this, the app checks the connection when it opens. If it can't
reach the server, it asks you to type in a different address instead of
just failing:

  1. Start the server on your machine (start.bat) and note the
     "other devices on this WiFi" address it prints, e.g.
     http://192.168.1.23:3000
  2. Make sure your phone is on the SAME WiFi network as that machine.
  3. Open the app. If the default server isn't reachable, you'll be
     prompted for a different address — enter the one from step 1.
  4. The address is remembered on the device, so you only need to redo this
     when you move to a different WiFi network (the address will change).

You can also change the address proactively at any time: on the login
screen (or the offline screen), tap the small "Server: ..." text near the
bottom.

--------------------------------------------------------------------------------
6. TROUBLESHOOTING
--------------------------------------------------------------------------------

- "Node.js was not found" / "version too old" — accept the auto-install
  prompt (needs winget, built into Windows 10/11), or install the LTS
  version (18+) manually and re-run.
- "Java (JDK) was not found" — accept the auto-install prompt (installs
  Eclipse Temurin JDK 17), or install a JDK manually and re-run.
- Auto-install says it finished but the script still can't see it — close
  the window, open a new one, and re-run. A running window keeps the PATH
  it started with, so a brand new install only becomes visible in a fresh
  window.
- "npm install failed" (after the above checks pass) — usually a network
  issue; check your internet connection and try again.
- Server starts but the app can't reach it from a phone — check that both
  devices are on the same WiFi network, and that Windows Firewall isn't
  blocking Node.js (it may prompt the first time the server starts; allow
  it on Private networks).
- Gradle build fails and android\local.properties is missing — the SDK
  location isn't configured yet; open the android folder in Android Studio
  once so it can set that up, then re-run install-on-phone.bat.
- Gradle build fails with "Could not read workspace metadata" or similar
  cache errors — run repair-gradle.bat, then rebuild.
- Phone shows "unauthorized" during install — check the phone screen for a
  "Allow USB debugging?" prompt and accept it, then re-run
  install-on-phone.bat.
